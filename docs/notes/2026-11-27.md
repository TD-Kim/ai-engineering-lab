# 학습 노트 — 2026-11-27

## 16:23 — RTX 3070(8GB)에서 8B 모델을 돌릴 수 있나 (질문·답)

> 최종 서비스에서의 위치: LLM 선택(1-1의 "더 큰 로컬 모델" 선택지). 규칙 강화 실험의 "다음 할 일: 모델 변경"과 이어진다.

### 결론: 무리는 아니지만 "조건부"
- 기획서 §5-2: "7~8B LLM 4bit 추론: **조건부**, 여유 적음"

### 손계산: 모델이 차지하는 메모리
| 저장 방식 | 파라미터 하나 | 8B 모델 가중치만 | 8GB VRAM에 |
|---|---|---|---|
| fp16 (원래 크기) | 2바이트 | 8B × 2 = 16GB | 안 들어감 |
| 4bit 양자화 | 0.5바이트 | 8B × 0.5 = 4GB | 들어감 |
- **양자화**: 숫자를 덜 정밀하게 저장해 크기를 줄이는 방법. 품질이 조금 떨어질 수 있다.
- 4GB가 전부가 아니다. 여기에 더 붙는다:
  - 대화 길이만큼 늘어나는 메모리(**KV 캐시**): `num_ctx`가 클수록, 프롬프트가 길수록 는다
  - 실행에 필요한 기본 공간
- 그래서 "들어가긴 하는데 여유가 적다". 실제 사용량은 측정 필요.

### VRAM이 모자라면
- Ollama는 멈추지 않고 모델 일부를 **CPU·일반 메모리로 넘겨** 돌린다 → **훨씬 느려진다.** 오류가 안 나서 모르고 지나가기 쉽다.
- 확인 방법:
  - `ollama ps` → GPU / CPU에 몇 %씩 올라갔는지("100% GPU"면 좋음)
  - `nvidia-smi` → VRAM 사용량
- Ollama 기본 모델은 대개 4bit 양자화. 내려받을 모델이 어떤 방식인지는 모델 페이지에서 확인.

### 추천: 8B보다 `qwen2.5:7b`
| 이유 | 설명 |
|---|---|
| 바꾸는 것 하나만 (1-2) | 지금 1.5B와 **같은 계열** → 결과가 달라지면 "크기 때문"이라고 말할 수 있다. 다른 회사의 8B로 바꾸면 크기·학습 방식·토크나이저가 한꺼번에 바뀐다 |
| 라이선스 | 기획서 §6-1: Qwen2.5 7B는 Apache-2.0. 다른 8B는 따로 확인 필요 |
| 크기 | 7B가 8B보다 조금 작아 여유가 약간 더 있다 |

### 실험에 쓸 때
1. 실험 1(A·B·C × seed 5개 = 15번)을 **1.5B로 먼저** 끝내 기준선을 만든다.
2. **똑같은 코드와 seed**로 모델 이름만 `qwen2.5:7b`로 바꿔 다시 돌린다.
3. "문서에 없습니다" 횟수와 함께 **속도**(TTFT, 토큰/초)와 **VRAM 사용량**도 기록한다 → "품질이 얼마나 올랐고, 그 대가로 얼마나 느려졌나"를 함께 말한다(HANDOFF의 "Ollama 모델 측정"도 여기서 채움).

### 정리
- 8GB에서 7~8B는 **4bit로만, 여유 없이** 돌아간다. GPU에 다 올라갔는지 꼭 확인하고, 비교 실험이라면 같은 계열인 `qwen2.5:7b`.

### 미확인
- `qwen2.5:7b` 4bit의 실제 VRAM 사용량, `num_ctx`에 따른 증가량, 1.5B 대비 속도
