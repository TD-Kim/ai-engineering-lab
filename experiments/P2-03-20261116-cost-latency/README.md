- 실행 위치: 클라우드 작업 환경(API 키 없음). 아래 "결과(데모)"는 **가짜 SDK가 캐시를 흉내 낸 것**(토큰 = 글자 2개당 1, 지연 = 미리 정한 값)이며 Claude 실제 결과가 아니다. **실제 측정 표는 사용자 PC에서 채울 칸**이다.

## 목적
(1) 고정 앞부분 + 바뀌는 질문 구조에서 캐시 쓰기 → 읽기 → (시스템 프롬프트에 시각을 넣으면) 다시 쓰기가 실제로 일어나는지, (2) 캐시 읽기의 비용 절감과 지연 변화, (3) 배치 결과가 돌아오는 데 걸리는 시간과 비용을 확인한다.

## 관찰
- 가짜 SDK 기준: 같은 앞부분을 두 번째 요청이 읽으면 그 요청의 실제 비용이 캐시 없을 때의 약 1/3이 되었다(쓰기 1회는 오히려 비쌈). 시스템 프롬프트 맨 앞에 시각을 붙이자 `first_divergence`가 `system[0]`의 0번째 글자를 가리켰고, 앞부분 전체가 다시 쓰였다.
- 실제 모델의 토큰 수·지연 차이는 측정 전이다(위 표).
